## One generated-media scenario

Run on an isolated Linux Docker host, from this checkout, after explicit host
authorization if it is remote. No server access/deployment has been performed.
The scenario passed locally in Docker Desktop’s Linux/arm64 VM with Sonarr
4.0.20.3014 and Prowlarr 2.6.5.5623. No application fix was needed. The prior
Docker connection failure did not establish that Docker Desktop was down.

Use a fresh project named `anibridge-query-acceptance`. Never combine the
acceptance overlay with `show.yaml` or point it at retained Bunny/real volumes.
The existing seed creates generated Breaking Bad metadata; only TVDB 81189
S01E01, English-sub variant, is grabbed. Sonarr may fetch that fixed descriptor/
artwork. Neither provider metadata nor provider video is fetched.

`generate.py` creates a 601-second test pattern/sine MP4 offline, <=16 MiB,
60-second generator deadline. `sitecustomize.py` is a **test-only network input
fixture** loaded through the overlay's PYTHONPATH: exactly one provider page,
one Vidoza-shaped player page and the generated bytes. DNS/TLS/HTTP for these
three fake HTTPS URLs are simulated. Other fixture paths are refused.
Do not copy that hook into an installation or normal Python environment.

The actual production path remains:

1. Sonarr queries Prowlarr → AniBridge → metadata API.
2. Sonarr performs the sole `POST /release`, which calls AniBridge's real
   qBittorrent add route and durably admits the self-contained job.
3. Normal `app.main` lifespan starts `Runner`/`SubprocessExecutor`.
4. Actual `job_child` resolves the synthetic offers with the maintained parser,
   streams bytes through production yt-dlp transport and reports progress.
5. Actual remux/probe/receipt children verify and publish the MKV; production
   `Jobs.finish` records completion. No fabricated outcome or DB status update.
6. Sonarr's completed-download handling imports it through the shared path.

No restart or retry is needed for this single happy-path case. If a job blocks/
fails or import fails, this run fails: retain diagnostics and stop. Do not force
completion, copy media into the library, introduce a fallback or broaden tests.

```sh
# Repository root. These commands are for the operator, not a deployment action.
df -h .
export PILOT_COMMIT=$(git rev-parse HEAD)
export COMPOSE_FILE=scripts/catalog/query_pilot/compose.yaml:scripts/catalog/query_pilot/clients.yaml:scripts/catalog/query_pilot/acceptance.yaml
docker info
docker compose -p anibridge-query-acceptance config --quiet
docker compose -p anibridge-query-acceptance build
docker compose -p anibridge-query-acceptance up -d catalog api sonarr prowlarr
timeout 12m docker compose -p anibridge-query-acceptance exec -T --user 1000 api \
  python /pilot/acceptance/run.py
# Preserve the bounded result before stopping the disposable stack:
docker compose -p anibridge-query-acceptance exec -T api \
  cat /data/acceptance-result.json
docker compose -p anibridge-query-acceptance down
```

The library is a **separate volume** at `/library`, writable only to the client
for this scenario; both sides see `/downloads`. No remote-path translation is
needed. Metadata service 512 MiB/2 CPUs, AniBridge 1 GiB/2 CPUs/no swap; client
limits/images/log rotation are inherited from the pinned client overlay.
The generator exits. There is no long-running producer, scheduled run or scrape.
Stop with `down` even when the acceptance command fails; retain volumes first.
For another clean run, remove **only this acceptance project's** disposable
volumes with the same files/project and `down -v --remove-orphans`. Never delete
the `anibridge-query-bunny-pilot` or original generated rehearsal volumes.

Expected PASS means the script actually verifies all of:

- Existing queues/library initially empty; both real clients register/test.
- One approved Unknown release, one Sonarr-initiated grab through Prowlarr.
- Durable job `completed`, exactly one attempt; qBittorrent progress 1 and a
  real content file under `/downloads` with `.verified-output.json`.
- Recorded provider/player/media reads originate from `job_child.py`.
- Sonarr episode-file record for S01E01 and a file under `/library`; SHA-256
  equals the published MKV, ffprobe finds video/audio and >600-second duration.
- JSON contains `acceptance: passed`; no helper writes a completed job row.

The passing run proves generated-input resolution/transfer, actual production
job completion and Sonarr import of generated media. It does **not** prove real
provider extraction, TLS/DNS security, host uptime, signed URLs or import of
provider media. The imported file matched the published MKV SHA-256. Job
admission → completion took 4 seconds at database timestamp precision; input
7,791,146 bytes, published/imported file 7,862,192 bytes. Container lifetime
memory peaks were 696,487,936 bytes for AniBridge and 67,956,736 bytes for
metadata serving, below their 1-GiB/512-MiB limits. This is a short one-job
measurement, not collector capacity or endurance proof.

```sh
docker run --rm -i --network none \
  -v anibridge-query-bunny-pilot_local-state:/retained:ro --entrypoint python \
  anibridge-query-api:0ce826fd30eba0cf8c0772a53e0695331028feb0 - <<'PY'
import json, shutil, sqlite3, tempfile
from pathlib import Path
with tempfile.TemporaryDirectory() as temporary:
    for suffix in ('', '-wal', '-shm'):
        source = Path('/retained/anibridge_jobs.db' + suffix)
        if source.exists():
            shutil.copy2(source, Path(temporary) / source.name)
    with sqlite3.connect(Path(temporary) / 'anibridge_jobs.db') as db:
        rows = db.execute('SELECT j.status FROM clienttask c LEFT JOIN job j ON j.id=c.job_id').fetchall()
    print(json.dumps(rows))
    assert rows == [], 'retained queue is not empty; inspect without starting jobs'
PY
```

This confirms empty persisted queue state; it is not another client discovery
run or a new completion/import gate. Do not start a live queue if it is nonempty.
